# Переговорный штаб (Arena переговоров)

Полное руководство по продукту и его технической части собрано в [DOCUMENTATION.md](DOCUMENTATION.md). Исходное техническое описание также сохранено в [TECHNICAL.md](TECHNICAL.md).

Прототип хакатон-концепта **C**: учебный симулятор переговоров с ИИ-оппонентом, внутренним советником, «температурой сделки» и итоговым отчётом.

Стек: **Next.js App Router + TypeScript + Tailwind**. UI на русском.

## Быстрый старт (mock, без ключей)

```bash
cd negotiation-arena-app
cp .env.example .env.local
# LLM_MOCK=1 уже в примере — mock включён
npm i
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000).

- **Игрок** (`/`): начать с трёх разных ситуаций — пилот, дедлайн, повышение зарплаты — либо выбрать один из девяти учебных сценариев каталога → пройти раунд → получить исход, оценки навыков, цитаты из своих реплик и ссылки на теорию → повторить сценарий с одним изменённым условием и сравнить результаты.
- **Админ** (`/admin`): создать или отредактировать сценарий, сохранить черновик, проверить его в предпросмотре и опубликовать.

В каталоге доступны девять сценариев: повышение зарплаты и пять кейсов о скидке, росте цены поставщика, конфликте в команде, вопросах партнёра и неясных ролях, плюс три исходных кейса. Три стартовые карточки показывают кейсы о пилоте, дедлайне и карьере. Все сценарии и реплики оппонентов работают в детерминированном mock-режиме без ключей.

## Groq LLM

Тонкий клиент: `src/lib/llm/client.ts`.

| Переменная | Назначение |
|---|---|
| `GROQ_API_KEY` | Ключ Groq API; хранить только в `.env.local` |
| `GROQ_MODEL` | ID модели; по умолчанию `openai/gpt-oss-120b` |
| `LLM_MOCK` | `1` — принудительный mock |

Запрос: `POST https://api.groq.com/openai/v1/chat/completions` с `Authorization: Bearer …`. Используется существующий HTTP-клиент без дополнительного SDK.

Если ключ отсутствует, запрос падает или `LLM_MOCK=1` — используются детерминированные mock-ответы. При ошибке Groq сервер пишет статус в лог. Секреты не коммитить: `.env.example` содержит только пустое поле ключа.

Для живого API создайте ключ в [Groq Console](https://console.groq.com/keys) и задайте в `.env.local`:

```bash
GROQ_API_KEY=ваш_ключ
GROQ_MODEL=openai/gpt-oss-120b
LLM_MOCK=0
```

Проверка живого подключения после запуска приложения с `LLM_MOCK=0` и заданным ключом:

```bash
curl -sS -X POST http://localhost:3000/api/character \
  -H 'Content-Type: application/json' \
  -d '{"role":"директор по закупкам","sphere":"IT","tone":"деловой"}'
```

В ответе `mock: false` означает, что ответ получен от Groq; `mock: true` означает запасной режим. На экране `/admin` источник ответа также указан после генерации персонажа.

## Сборка

```bash
npm run build
npm start
```

`npm run dev`, `npm run start` и `npm run build` используют общий `.next`. Перед пересборкой остановите работающий сервер: замена артефактов под запущенным процессом может вызвать `Cannot find module './*.js'` или загрузку страницы без CSS (404 старого хеша). Если это произошло, остановите сервер, выполните `npm run build` и заново запустите `npm run start`; для dev достаточно перезапуска `npm run dev`. Проверяйте не только HTML, но и успешную загрузку stylesheet и реальную ширину страницы. Эта проверка не заменяет визуальную приёмку.

`GET /api/health` возвращает статус локального приложения. После `npm run dev` можно выполнить сквозной mock smoke-check обоих исходов: `BASE_URL=http://127.0.0.1:3000 npm run smoke`.

### Проверка в среде с ограниченной сетью

Если `npm ci` завершается сообщением `Exit handler never called!`, проверьте npm-лог: причиной может быть `ENOTFOUND registry.npmjs.org`. Смена каталога npm-кэша сама по себе эту ошибку не устранила; установка прошла после предоставления сетевого доступа. Сборка также загружает Inter и JetBrains Mono через `next/font` и в среде без доступа к `fonts.googleapis.com` завершалась ошибкой. После разрешения сетевого доступа `npm ci`, `npm run lint` и `npm run build` прошли. Это не проверяет живой Groq API без `GROQ_API_KEY`.

## Хранение сценариев и Neon

Без `DATABASE_URL` приложение использует локальные `data/*.json`. С подключением Neon сценарии, попытки, профили, комнаты, участники, переписка и очередь подбора сохраняются в PostgreSQL. Ошибка настроенной БД не переключает приложение на JSON: это предотвращает расхождение данных между экземплярами.

Для режима БД нужны Node.js 22+ и одинаковые на всех экземплярах `DATABASE_URL`, `ADMIN_API_TOKEN`, `SESSION_SECRET`. Последние два значения — независимые случайные секреты, не менее 32 символов. В текущей локальной `.env.local` они уже сгенерированы; на хостинге их нужно добавить в окружение отдельно. Секреты не публикуйте и не коммитьте.

`/admin`, чтение скрытого сценария и публикация защищены `ADMIN_API_TOKEN`. Браузер запрашивает Basic-вход: имя — любое, пароль — этот секрет; затем использует HttpOnly-cookie. API также принимает `Authorization: Bearer`. Черновой пробный раунд требует того же доступа. Без БД и без секрета административный доступ открыт только в dev-демо; production закрывается по умолчанию.

Миграции хранятся в `db/migrations/`. Для сопровождения через Neon используйте плагин: проверьте изменения на отдельной ветке, затем примените SQL-файл и его запись `_migrations` одной транзакцией. Для самостоятельного запуска есть `npm run db:migrate`; мигратор предпочитает `DATABASE_URL_UNPOOLED` / `POSTGRES_URL_NON_POOLING`. Запускайте один мигратор за раз.

Для переноса существующего демо подготовьте пакет `npm run db:prepare-import -- /private/tmp/arena-import.json` и примените `statements` из него через Neon SQL transaction. Перенос добавляет отсутствующие ID, сохраняет существующие строки БД и исходные JSON. Временная очередь подбора не переносится. Старые попытки без профиля сохраняются как архив и не выдаются анонимным участникам. Файл пакета содержит учебную переписку и скрытые настройки: храните его локально, после переноса удалите.

Публичные DTO скрывают инструкции, интересы, ограничения и правила оппонента. В DB/public-режиме попытки и прогресс доступны по случайному ключу профиля в `x-profile-id`; браузер передаёт его автоматически. Это анонимный доступ по секретному ключу, без аккаунта и восстановления по email. На `/progress` можно сохранить файл доступа и открыть его на другом устройстве в том же приложении. Потеря файла и данных браузера означает потерю доступа.

«Удалить историю» удаляет все попытки и отчёты профиля, сохраняя псевдоним и настройки. `DELETE /api/progress?profileId=...` удаляет и профиль; `scope=history` — только попытки. Удаление отдельной попытки доступно через `DELETE /api/attempts/[id]`. Рейтинг выключен по умолчанию: он показывает псевдоним и сопоставимый результат, фильтруется по версии, сложности, самостоятельному режиму и периоду. Отключение публикации убирает результат из рейтинга.

## Демонстрационный маршрут

1. Запустите `cp .env.example .env.local && npm install && npm run dev` без ключа Groq (`LLM_MOCK=1`).
2. На `/` выберите кейс; например, «Клиент требует скидку».
3. В mock-режиме уточните причину запроса и обменяйте уступку на встречное условие. Для альтернативного исхода обещайте скидку без встречного обязательства.
4. Завершите раунд. Цитаты отчёта берутся из сохранённых сообщений; ссылки ведут на `/learn`. Выберите одно новое условие для повтора. После повторного раунда отчёт покажет изменение условия и разницу результатов.
5. На `/admin` задайте роль, интересы и правила исходов; сохраните черновик, проверьте его через предпросмотр и опубликуйте. Новая версия применяется к новым попыткам; активные попытки продолжают использовать сохранённый снимок.

Идентификаторы событий и оценки — прозрачные учебные эвристики по тексту реплик, а не объективная оценка переговорщика. БД, доступ и межэкземплярная согласованность проверяются отдельно от качества учебной оценки и production-приёмки.

## Групповые комнаты и сброс локального демо

На `/group` доступны приглашения в шаблоны «Клиент и продавец» и «Команда защищает план проекта», поиск случайного соперника для 1×1, а также индивидуальная практика против руководителя и заказчика-ботов. Ссылку-приглашение получает создатель; она резервирует одно место и перестаёт действовать после подключения второго участника. Реплики доступны только по случайному токену участника; на диск записывается его SHA-256-хеш. Роль и персональный бриф выдаются только по токену этой роли. Без подключения БД состояние комнаты и история хранятся в `data/group-rooms.json`, поиск соперника — во временном `data/group-matchmaking.json`; между перезапусками локального процесса данные комнат сохраняются, поиск ожидает не более трёх минут. Браузер хранит токен своей комнаты в localStorage.

JSON-хранилища (`data/attempts.json`, `data/group-rooms.json`, `data/group-matchmaking.json`) относятся к локальному демо. Явный сброс попыток, комнат и очереди перед демонстрацией:

```bash
npm run demo:reset -- --confirm
```

Без `--confirm` команда завершится, не меняя файлы. Сценарии `data/scenarios.json` и seed в коде остаются на месте. Обычный запуск ничего не очищает.

В режиме Neon приглашение, очередь, история и завершение обновляются в транзакциях. Одно место по приглашению занимает только один участник; результат подбора выдаётся однократно. Временные credentials выдачи зашифрованы AES-GCM; invite/member/search ключи хранятся как SHA-256-хеши. Для групповых изменений применяется короткая общая advisory-блокировка в БД, чтение использует согласованный снимок. Это решение для небольшой нагрузки; нагрузочное тестирование и разделение блокировок по комнатам остаются отдельной работой.

Участник может удалить общий диалог через `DELETE /api/group-rooms/[id]` со своим Bearer-ключом: удаляется вся комната, её участники, сообщения и связанные билеты. В парной практике это затрагивает обе стороны; перед удалением согласуйте действие. Билеты подбора действуют три минуты; сохранённые попытки/комнаты остаются до явного удаления. Локальный `demo:reset` очищает только JSON, БД он не трогает. Аккаунты, универсальный подбор по нескольким сценариям и автоматические тайм-ауты комнат ещё не реализованы.

## Проверка БД

```bash
NEXT_DIST_DIR=.next-db-verify npm run build
ARENA_TEST_DB_ENV_FILE=/private/tmp/neon-test.env npm run db:verify
# Дополнительно browser acceptance и снимки 1280/390/320:
ARENA_TEST_DB_ENV_FILE=/private/tmp/neon-test.env ARENA_BROWSER_VERIFY=1 npm run db:verify
```

Тестовый env-файл должен содержать `DATABASE_URL` отдельной ветки Neon. Тест поднимает два экземпляра на 3211/3212, проверяет гонки, доступ, версионирование, перезапуск, прогресс, рейтинг и удаление только собственных тестовых записей. Browser-проверка использует Playwright (`ARENA_PLAYWRIGHT_PACKAGE` задаёт путь пакета); `ARENA_BROWSER_EXECUTABLE` позволяет выбрать установленный Chromium. Отчёты — `docs/verification/`, снимки — `screenshots/YYYY-MM-DD/`.

Если ESLint проверяет скомпилированный `.next-db-verify` и выдаёт тысячи ошибок `require()`/`@ts-ignore`, причина — отсутствующий ignore для отдельной сборки. Этот каталог уже исключён в `eslint.config.mjs` и `.gitignore`; повторный lint проверяет исходники. Сборка в отдельном каталоге сохраняет работающий `.next` без замены его файлов.

## Out of scope

Полноценные аккаунты, полный граф сценариев, assessment suite, нагрузочная и deployment-приёмка.

При проверке на этой машине Chrome через Playwright не доставлял обычные pointer/keyboard события, хотя DOM-вызов click запускал форму. Проверенная замена — установленный Chromium headless shell через `ARENA_BROWSER_EXECUTABLE`: обычные `.click()`, загрузка/скачивание файла, перенос в отдельный контекст, удаление и ширины 1280/390/320 прошли. DOM-click не заменяет проверку пользовательского действия. Пакет Playwright и браузер должны быть доступны в среде проверок.
